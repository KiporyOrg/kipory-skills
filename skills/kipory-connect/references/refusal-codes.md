# Refusal codes

Every code the platform can refuse a builder with, once each: what it means and what to do. Look up the error envelope's `code`, a save-time finding's `code` (in `details.diagnostics[]`, a `validateOnly` verdict or a document plan), or the rule name in `details.reason`.

- **Branch on `code`, never on `message`.** A message's wording may change at any time; the codes here are the contract.
- **A code this page does not list is no longer sent.** When `scripts/sync.mjs` reports this page out of date, the deployment is newer than the page: read a code missing here as undocumented, not as retired.
- 44 codes that only staff or the platform itself can meet are left off.
- Each line: the code · where it appears (its HTTP statuses, a finding's severity, or `details.reason`) — what it means. **Remedy:** what to do. **Details:** the `details` members the remedy reads.

## Envelope `code`

- `ACTION_EVALUATE_BUSY` · 503 — The platform was too busy to give the action being evaluated a worker, so nothing of it ran. Nothing about the action is wrong. **Remedy:** Send the same request again after the `Retry-After` seconds; `details.actionKey` names the action. **Details:** `actionKey`.
- `ACTION_EVALUATE_SLOT_TRUNCATED` · 422 — The run's recorded trace holds the value this action reads cut short, so evaluating it on that value would mislead. `details.slot` names it. **Remedy:** Pass that slot's value in `slots`, or turn on recording for the flow and run it again with a smaller value. **Details:** `slot`.
- `ACTION_EVALUATE_TRACE_MISSING` · 422 — The run named in `fromRun` has no recorded values: its trace was not sampled, or it has expired; or it recorded none for a slot the action reads (`details.slots` names them), because the run did not reach their writers. **Remedy:** Turn on recording for the flow and run it again, pick a run that wrote those slots, or pass the values in `slots`. **Details:** `slots`.
- `ACTION_EVALUATE_UNSUPPORTED` · 422 — Evaluating one action runs only functions that read nothing but their inputs, and record reads; this action's function writes, calls a vendor or a model, or reads files or state. **Remedy:** Run the flow with `POST /v1/flows/{id}/preview` instead. `details.runnable` lists the functions evaluate runs. **Details:** `runnable`.
- `ACTION_HAS_DEPENDENTS` · 409 — The action was not deleted: another action in its flow reads a slot this one writes, as an input or in its condition. The message names the slot and the readers. **Remedy:** Re-point or delete the actions that read the slot first, then delete this one. Each action in the flow's action list carries this answer in advance as `deleteRefusal`.
- `BAD_REQUEST` · 400, 422 — The request was malformed in a way no schema check caught — for example a flow tried a blocked network request, or a search named a vector slot the collection does not carry. **Remedy:** Read the message: it says what was wrong with what you sent. When it opens with a rule name, that name is `details.reason`. Fix the request and send it again. **Details:** `reason`.
- `BALANCE_BELOW_SOFT_CAP` · 402 — The wallet that pays for this project has reached its floor (zero, less any overdraft), so a call that spends credits was refused. The same code answers for a suspended wallet, with `details.reason` `payer_suspended`. **Remedy:** No call a key can make adds credits: tell the human which wallet needs credit (`payer.name` and `payer.nodeId` on `GET /v1/credits/balance`). A suspended wallet is lifted only by whoever runs the deployment. **Details:** `reason`, `balance`, `softCap`.
- `CANNOT_ACT_ON_SELF` · 400 — A signed-in admin asked to change their own seat or delete their own account through the project's member management, which acts only on other members. **Remedy:** Ask another admin of the project to change your seat. To close your own account, use your own account settings instead.
- `CHANGE_SET_APPLY_FAILED` · 502 — The flow ran, but its changes could not be applied, so nothing was written. `details.cause` says why: a unique-constraint collision, a write the platform refused, a database error, or terms a vocabulary that admits one term per record could not hold (`one-term-vocabulary`, with `details.vocabularyKey` and `details.terms`). **Remedy:** With `details.cause` `database-error` a retry may succeed. With `unique-violation` or `write-refused` the same run fails the same way: check what the flow writes against the records already there. With `one-term-vocabulary`, file one term of that vocabulary per record in a run. **Details:** `cause`, `vocabularyKey`, `terms`.
- `CHANGE_SET_BOUND_EXCEEDED` · 502 — The flow ran but staged more changes than one run may apply, so nothing was written. `details.limitKey` names the limit, `runs.change-set-effects`. **Remedy:** An unchanged retry fails again. Make the run stage fewer changes — split the work over several runs, or write in batches. The limit's value for your project is on its limits list. **Details:** `limitKey`.
- `CHANGE_SET_NOT_FOUND` · 404 — No change set is kept for that run: the run does not exist, belongs to a project your key does not reach, or is past retention. The three answer alike. **Remedy:** Check the run id. A run past retention has no change set to read; its timeline may still hold what each action did.
- `CHANGE_SET_PRECONDITION_CONFLICT` · 409 — A record the run read changed while the run was in progress, so nothing was written. `details.recordId` is that record, and `details.readByActionId` the action that read it. **Remedy:** Send the same request again: the retry reads the current state and can succeed. If it keeps failing, something else writes that record at the same time. **Details:** `recordId`, `readByActionId`.
- `CONFIRMATION_MISMATCH` · 400 — The email typed to confirm deleting a member's account does not match that account's email (compared trimmed and case-insensitively), so nothing was deleted. **Remedy:** Type the member's email exactly as their account holds it and ask again. A dry run of the deletion shows which account it is.
- `CONFLICT` · 409 — The request conflicts with the current state — something already exists, is in use, or is not in the state the write needs. The specific rule, when there is one, is in `details.reason`. **Remedy:** Match `details.reason` first (with `details.issues` when present), and read the message: it names what is in the way. Change that state, then send the request again. **Details:** `reason`, `issues`.
- `DESIGN_BUSY` · 409 — Another change to this project's configuration was being applied or planned, and this one stopped rather than wait longer for it. Nothing was written. **Remedy:** Send the same request again after the `Retry-After` seconds. Nothing needs to change in it.
- `DESIGN_SPEND_CAP_EXCEEDED` · 402 — The project's design-time work — flow previews, action previews, eval runs — reached `designSpendCapCredits` on the project's settings for the current period. **Remedy:** Raise `designSpendCapCredits` on the project's settings, or wait for the period in `details.period` to roll over from `details.windowStart`. Topping up the wallet does not lift this ceiling. **Details:** `reason`, `consumed`, `cap`, `period`, `windowStart`.
- `DOCUMENT_RENAME_FORBIDDEN` · 403 — The project document renames a table, field, relation or vocabulary, which breaks callers that use the old word, and applying it needs the ADMIN role on the project. **Remedy:** Apply the document with a key or person holding ADMIN on the project, or ask an admin to apply it. A plan of the document lists each rename this refuses.
- `EMBEDDING_MODEL_UNAVAILABLE` · 503 — The embedding model did not answer the phrase (it failed or timed out), so nothing was searched by meaning and no partial ranking was returned. **Remedy:** Send the same search again shortly. In a flow, `onFailure: "continue"` on the `record.query` action carries the run past this failure.
- `END_USER_REQUIRED` · 403 — This route acts on one person's own things, so it needs that signed-in person's session on the project's host. An API key acts for the project, not for a person. **Remedy:** Call it from your app with the end user's session (the one their sign-in gave you) on the project's host, not with an API key.
- `EXPIRED` · 410 — The signed file link has passed its expiry, so the file was not served. The link was valid; only its time ran out. **Remedy:** Read the record or file again to get a fresh link, and use it promptly. Do not store signed links for later.
- `FLOW_FAILED` · 502 — The endpoint's flow failed, so nothing it staged was written: an action failed (`details.phase` says which kind, `details.action` names it by its key), the run reached a limit of how much one run may do (`details.class` is `limit` and `details.limitKey` names it), or its output does not fit the endpoint's response. **Remedy:** Read that action's row in the run's timeline for its message; `details.reason` is set when the action was refused for something you can fix, such as the project's daily mail or push cap. An unchanged retry usually fails the same way: fix the flow, its input, or the response it must produce. **Details:** `phase`, `action`, `reason`, `class`, `limitKey`.
- `FLOW_HAS_DEPENDENTS` · 409 — The flow was not deleted because something still references it — an endpoint, schedule (disabled ones too), trigger, bound table, vocabulary resolver, or another flow's `flow.invoke`. `details` counts each kind. **Remedy:** Delete or re-point each dependent the message names, then delete the flow — or delete the calling flows in the same project document, which deletes callers first. A dry run of the delete (`validateOnly`) answers the same question without the 409.
- `FLOW_INPUT_BLANK` · 422 — A schedule or trigger gives one of its flow's declared inputs an empty value (empty string, null or empty list). It fires with nobody to fill the gap, so it is refused when saved. **Remedy:** Give every input the flow declares a real value in the schedule's or trigger's inputs; `details.issues` names each blank one. **Details:** `issues`.
- `FLOW_OUTPUT_MISSING` · 422 — No action failed, but the flow produced no value for a required output, so nothing the run staged was written. `details.missing` names the outputs. **Remedy:** Not retryable as is: fix the flow so an action writes each missing output (or bind it), or change the input that made the producing action skip. **Details:** `missing`.
- `FLOW_SIGNATURE_ADOPT_CROSS_PROJECT` · 409 — The flow's signature change asked to adopt captured copies, but other projects also hold a copy; each resolves the flow's types in its own project, so one re-capture cannot serve them all. **Remedy:** Unbind the holders in the other projects, or re-point them, before changing the signature. `details.foreignProjects` says how many projects hold one. **Details:** `foreignProjects`.
- `FLOW_SIGNATURE_LOCKED_BY_DEPENDENTS` · 409 — Changing the flow's inputs or outputs (or restoring a checkpoint that does) would re-shape the captured signature that endpoints, schedules or triggers hold. `details` counts the holders by kind. **Remedy:** Send the flow's update again with `adoptSnapshots: true` to update the holders with it, or unbind them first. Every client of an affected endpoint then sees the new shape at once.
- `FORBIDDEN` · 403 — The credential may not do this: its grant does not reach the node, its role is below the route's floor, or the route refuses this kind of caller. An unknown node answers the same. **Remedy:** Match `details.reason` first. With `insufficient_project_role`, compare `details.grant` with `details.requiredRole`: if the role already meets it, the node is outside the key's grant. Otherwise the message says what is refused. **Details:** `reason`, `requiredRole`, `grant`.
- `GATEWAY_TIMEOUT` · 504 — A synchronous endpoint's flow did not finish within the endpoint's wait (`syncWaitMs`). The answer is lost, but the run may have completed and made its changes. **Remedy:** Check whether the run's changes were made before you retry: a retry with the same `Idempotency-Key` does not repeat its record changes, but it does repeat its messages and outside calls. To stop the timeouts, make the flow faster, raise the endpoint's `syncTimeoutMs` up to the ceiling, or make the endpoint asynchronous and read the result when it is ready.
- `HANDOFF_CODE_INVALID` · 401 — The one-time sign-in code could not be exchanged: it is unknown, expired, already used, another project's, or sent with the wrong `state`. All of these answer alike. **Remedy:** Send the person through sign-in again and exchange the new code at once, from your server, on the project's host. Never retry the exchange with the same code.
- `HOLDER_NOT_WRITABLE` · 422 — A `source.watch` or `source.unwatch` action's holder is not a record the run may write — a record of the person the run acts for, or a shared one. A missing id answers the same. **Remedy:** Point the action's `holder` at a record the run may write, usually the record that stands for the follow. In a run for a person, `userId` may name only that person.
- `IDEMPOTENCY_KEY_REUSED` · 422 — The `Idempotency-Key` was already sent, within the last day, with a different request — another method, path or body. A key names one request; its retries converge onto that request's writes and charges. **Remedy:** Send a new key with each new request, and reuse a key only to retry the same request unchanged.
- `IDEMPOTENCY_KEY_TOO_LONG` · 422 — The `Idempotency-Key` is longer than 255 characters. **Remedy:** Send a key of at most 255 characters; a UUID is enough to name one request.
- `IDENTITY_LINK_LOST` · 422 — The sign-in provider's account is linked to no account here, and the provider shared no email to create one with — usually a returning person whose account was deleted. **Remedy:** Tell the person to remove the app from their provider's app settings and sign in again, so the provider shares their email.
- `INTERNAL` · 500, 503 — Something failed on the platform's side that no other code names. An endpoint's failed flow is `FLOW_FAILED`, never this. **Remedy:** A 503 can be retried shortly. For a 500, file a report with `POST /v1/reports` and put the `requestId` in its `requestIds`.
- `KEY_NOT_FOUND` · 404 — No API key by that id is yours to manage: it does not exist, was deleted, or sits at a node you do not administer. The three answer alike. **Remedy:** Check the key id against the keys you can list. A key you do not administer is managed by an admin of the node it was granted at.
- `LINK_FILTER_UNDECLARED` · 422 — A read of a record's links filters or counts by a property the relation does not declare as a link filter. It is refused rather than answered by scanning every link. **Remedy:** Use one of the filters in `details.declared`, or declare the property in `element.filters` on the table's link use for that relation, then ask again. **Details:** `undeclared`, `declared`.
- `LINK_REFUSED` · 422 — The link was not written. `details.reason` says why: a link to itself, a pair of tables the relation does not declare, properties it does not accept, a repeat, or a cardinality limit. **Remedy:** Fix what `details.reason` names — link two different records of a declared pair, or send only the properties the relation declares. A `record.link-assert` action leaves the same as a warning. **Details:** `reason`.
- `MEMBER_NOT_FOUND` · 404 — No such member on this project: the person never joined, left, was deleted, or (for a credit grant) holds no active seat. Each answers the same. **Remedy:** Check the user id against the project's member list. A suspended member must be restored before they can be granted credits.
- `MEMBER_WALLET_EMPTY` · 402 — A signed-in member's own wallet in this project is at zero or below, and nothing else pays for them. Credit in the project's wallet does not help. **Remedy:** Wait for `details.nextGrantAt` (null when the project makes no regular grant), or have an admin grant that member credits. `details.balance` is their balance. **Details:** `reason`, `balance`, `nextGrantAt`.
- `NOT_FOUND` · 404 — Nothing answers at that address for this caller: an unknown host or route, a wrong method, a disabled route group, an endpoint whose flow is gone, or an id you cannot see. **Remedy:** Check the host, path and id, and that your key reaches the project. When present, `details.reason` names the specific rule. An id in a project your key does not reach looks the same as a missing one. **Details:** `reason`.
- `NOT_NODE_MEMBER` · 403 — Reading this node needs a role on it, and the caller holds none. An unknown node answers the same, so the refusal says nothing about whether it exists. **Remedy:** Check the node id against what your key or session reaches. A person who should see it needs an invitation to the node.
- `NOT_NODE_OWNER` · 403 — Creating a project or organization needs the OWNER role on the parent node, and the caller holds less there (or the parent is unknown). **Remedy:** Create it with a key or person holding OWNER on the parent organization, or ask an owner of that organization to create it.
- `NO_BOUND_TABLES` · 422 — The flow's coverage report was refused because no table in the project binds the flow, so no processing attempts can be counted toward it. An empty report would read as complete coverage. **Remedy:** Bind the flow to a table as its processing flow (the table's `flowId`) and let records run through it, then ask for coverage again.
- `OWNER_FIELDS_NOT_READABLE` · 422 — A query's link clause filters on the fields, terms or link properties of records that belong to people, and the run acts for nobody, so it may only count those links. **Remedy:** Count the links instead of filtering on the far records, or run the query in a flow that acts for the person whose records they are.
- `PAYING_WALLET_CANNOT_COVER` · 422 — A credit grant to a member was refused: the wallet the project is paid from cannot cover `details.amount`, or is not active (`details.reason` says which). **Remedy:** Grant a smaller amount (at most `details.available`), or have the paying wallet credited by whoever runs the deployment. An inactive paying wallet funds no grant until it is active again. **Details:** `reason`, `available`, `amount`.
- `PAYLOAD_TOO_LARGE` · 413 — The request body, uploaded file or project document is larger than its limit, so nothing was stored. `details.limitKey` names the limit when one applies. **Remedy:** Send less: split the document or the data over several requests, or shrink the file. The limit's value for your project is on its limits list under `details.limitKey`. **Details:** `limitKey`.
- `PLAN_STALE` · 409 — The plan no longer says what applying it would do: since it was made, the rows it changes, or what removing them takes along, changed (`details.reason` `changed`), or the read it is based on is older than the history the platform keeps (`read-too-old`). Nothing was written. **Remedy:** Read the project again, plan your change against what it says now, read the new plan, and apply that one. Never resend an old document. **Details:** `reason`, `rows`, `changeLogFrom`.
- `PLAN_UNKNOWN` · 404 — No plan with this id can be applied in this project: it was applied already (`details.reason` `applied`, with `appliedVersion` and `appliedBy`), it is over 24 hours old (`expired`), the same planner kept too many newer plans (`evicted`), or it never existed here (`unknown`). Reading a plan an earlier release made answers it too (`outdated`). **Remedy:** Plan the document again and apply the new plan's `planId`. If it was applied already, read the project: your change is in. **Details:** `reason`, `appliedVersion`, `appliedBy`.
- `PLATFORM_DEPENDENCY_UNAVAILABLE` · 503 — The platform's own failure: one of its vendor or model-provider accounts refused an action's call, the engine failed, the database refused the run's changes, or a check made before serving (the credit check, a public endpoint's rate count, the sign-in settings) failed. Nothing was written, and nothing is charged. **Remedy:** Nothing in the request or flow needs changing: retry after `details.retryAfterSeconds`. `details.action` names a failed action and `details.class` the platform class. Whoever runs the deployment is alerted to each of these: a refused platform account and a run the platform failed where they happen, and a check that failed before serving once several requests fail within five minutes — if it persists, tell them. **Details:** `phase`, `action`, `class`, `retryAfterSeconds`.
- `PREVIEW_TEMPLATE_ERROR` · 422 — An action preview could not render the action's template: the interpolation failed on the input you gave. The message is the template error itself. **Remedy:** Fix the template in the action's `config`, or the sample input that does not fit it, as the message says, and preview again.
- `PROFILE_NOT_CONFIGURED` · 409 — The project has no end-user profile connected, so there is no profile to read or write for a person. **Remedy:** Connect a type you authored as the project's end-user profile first, then read or write profiles.
- `PROFILE_PINNED_BY_USER_PROFILES` · 409 — End users already hold profiles written from the connected profile type, so connecting a different type would strand their values. Editing the current type is not blocked. **Remedy:** Keep the connected profile type and edit it instead; a different type can be connected only once no end-user profiles remain.
- `PROFILE_TYPE_NOT_ELIGIBLE` · 422 — The type cannot be connected as the end-user profile: it is not one you authored, or it is not an object schema whose defaults satisfy it. **Remedy:** Connect a type you authored, as an object schema in which every required field has a default.
- `PROJECT_ACCESS_UNAVAILABLE` · 403 — The person signed in, but could not be given a seat on this project — usually because their seat here is suspended — so no session was made. **Remedy:** A project admin checks that person's standing among the project's members and restores the seat if it should be active.
- `PROJECT_ADDRESS_TAKEN` · 409 — The project address (subdomain) asked for is already taken, so the project was not created or renamed. A different address would succeed. **Remedy:** Choose another address and send the request again; the message says why this one is unavailable.
- `PROJECT_CONCURRENCY_EXCEEDED` · 429 — The project already has its maximum of requests running or streams open (`details.kind`), counted per api process; with `details.scope` `caller`, one address holds its share of public calls. **Remedy:** Wait `details.retryAfterSeconds` (also in `Retry-After`) and send it again; slow callers down rather than retrying at once. `details.limitKey` names the limit. **Details:** `scope`, `kind`, `limit`, `limitKey`, `retryAfterSeconds`.
- `PROJECT_NOT_RETIRED` · 422 — A purge was asked of a project that is still serving. Only a retired project can be purged ahead of its grace period. **Remedy:** Retire the project first (delete it), then ask for the purge if you do not want to wait for its `purgeAfter`.
- `PUBLIC_ENDPOINT_UNAVAILABLE` · 402 — A public endpoint (`auth: "none"`) was refused, with no `details`: the wallet or the public spend cap refused it, the project has no wallet to charge, or the run refused a caller nobody knows. **Remedy:** Read the row in `GET /v1/rejected-requests`: `gate` `wallet` means credit the wallet — and if the wallet has credit, the project has no wallet to charge, which only whoever runs the deployment can fix; the platform's critical "payer not found" alert tells them, so ask them only if it lasts; `public-spend-cap` means raise `publicSpendCapCredits` or wait for 00:00 UTC; no `gate` means the project is suspended or the flow needs a signed-in user.
- `QUERY_CLAUSE_TOO_BROAD` · 422 — The first exact clause of a query selected more records than the cap (or ran past its time budget) before any other clause could narrow it. **Remedy:** Add a narrower clause the planner runs first — a term or a field equality — or narrow this one. Reordering your clauses does not help: the order is the planner's. **Details:** `clause`, `cap`.
- `QUERY_CLAUSE_UNROUTED` · 422 — A query clause filters on a field, vocabulary, relation or link property the table's `uses` do not route, so nothing could answer it without scanning. The message names the field and the use to declare. **Remedy:** Declare the use the message names on that field (for a relation asked from its far end, ask `direction: "incoming"`). If the use was just declared, ask again in a few seconds.
- `QUERY_LIKE_RECORD_NOT_FOUND` · 422 — The record a `semantic` clause asks to resemble does not exist, or is not one this query may read. **Remedy:** Check the id `likeRecordId` gives and, for a record of another table, `likeTableKey`.
- `QUERY_LIKE_RECORD_NOT_INDEXED` · 409 — The record to resemble has no entry in the search index yet, so there is nothing to compare with. An empty answer would read as nothing resembling it. **Remedy:** Indexing follows processing: ask again once the record is ready, or run the search from a flow that fires after the record is processed.
- `QUERY_LIKE_TABLE_MODEL_MISMATCH` · 422 — The record to resemble is on a table with a different search model from the queried table, or on a table that is not searchable, so the two cannot be compared. **Remedy:** Resemble a record of a table on the same embedding profile as the queried one, or put both tables on one search model.
- `QUERY_PASSAGE_WITH_LIKE_RECORD` · 422 — A `semantic` clause asks for `passage` while resembling a record. A record is compared by several of its parts, so no single passage is the match. **Remedy:** Drop `passage` from the clause, or resemble a phrase (`text`) instead of a record.
- `QUERY_PEER_DEPTH` · 422 — A link clause's `peer` holds a clause other than `field`, `term` or `semantic`. A peer is one hop, so a link or stream clause inside it would be a second. **Remedy:** Keep only `field`, `term` and at most one `semantic` clause in `peer`; ask for a further hop with a flow that runs a second query.
- `QUERY_PEER_SCORE_MEMBER` · 422 — A `semantic` clause inside a link's `peer` carries a scoring member such as `minScore` or `passage`. A peer's phrase only chooses which records are in reach and gives no scores. **Remedy:** Remove the scoring members from the peer's clause; put them on the query's own `semantic` clause if you need them.
- `QUERY_SEMANTIC_MULTIPLE` · 422 — The query holds more than one `semantic` clause, counting those inside a link's `peer`. Two rankings have no defined merge. **Remedy:** Keep one `semantic` clause; narrow by the other with `field` or `term` clauses, or run it as a second query.
- `QUERY_SEMANTIC_SOURCE_AMBIGUOUS` · 422 — A `semantic` clause gives both a phrase and a record to resemble, or neither, or names `likeTableKey` with no record — or a query of several tables leaves the record with no table. **Remedy:** Give the clause exactly one of `text` and `likeRecordId`, and send `likeTableKey` only beside a record (always, when the query names several tables).
- `QUERY_TABLES_MODEL_MISMATCH` · 422 — A query names several tables that use different search models, so their records are not in one space and their scores cannot be ranked together. **Remedy:** Put the tables on one search model, or ask one query per model.
- `QUERY_TABLES_NEED_SEMANTIC` · 422 — A query names several tables but holds no `semantic` clause of its own. A query of several tables answers one ranking by meaning, and a peer's phrase does not rank. **Remedy:** Add a top-level `semantic` clause, or query one table at a time.
- `QUERY_TOO_BROAD` · 422 — A records page read or its count did not finish within its time budget — typically a very short phrase over a large table. **Remedy:** Narrow the read — a longer phrase, a status, a date range or a condition on a declared field — and ask again.
- `QUERY_TOO_MANY_CLAUSES` · 422 — The query holds more than 16 clauses, the most one query may have. **Remedy:** Cut the clauses to 16 or fewer; a question that needs more is a flow that runs several queries.
- `QUOTA_EXHAUSTED` · 429 — An action of the endpoint's flow met a quota that starts again later: a third-party service's quota, such as the YouTube Data API's daily units, or the credit of the project's own key at a provider. It is the project's quota, not your caller's, and no `Retry-After` is sent. A limit of how much one run may do is `FLOW_FAILED`, and so are the daily mail and push caps. **Remedy:** Do not retry in a loop: the same call fails until the quota starts again or the account is topped up. When `details.limitKey` is set, look that limit up on `GET /v1/projects/{nodeId}/limits`; a third party's quota resets on its own schedule. **Details:** `limitKey`.
- `RATE_LIMITED` · 429 — A rate limit was reached; `details.limitKey` names it and `details.windowMs` its window. Nothing was run and nothing was charged. **Remedy:** Wait `details.retryAfterSeconds` (also in `Retry-After`) and send it again; read the `x-ratelimit-*` headers and slow down before the ceiling. **Details:** `limitKey`, `limit`, `windowMs`, `retryAfterSeconds`, `scope`.
- `RECORD_BULK_REFUSED` · 422 — At least one item of a bulk write was refused, so nothing was written: a bulk writes all its items or none. Each entry of `details.issues` names its item and carries that item's own code. **Remedy:** Fix every item `details.issues` names (its `path`, such as `items.3`) and send the bulk again. Ask `validateOnly: true` first to see what each item would do. **Details:** `issues`.
- `RECORD_DATA_INVALID` · 422 — The record's data does not match what its table declares — the message lists each field and why — or the table points at a data shape the project no longer holds. **Remedy:** Fix the fields the message names and send it again. If the table's data shape is gone, repair the table's type first; no data can pass until then.

- `UNION_FIELD_TYPE_MISMATCH` · error — A prompt template reads `{{slot.field}}` from a slot that can be one of several types, and that field's type differs between them. **Remedy:** Use a field all the types share with one type (`details.intersection`), or narrow the slot to one type first. **Details:** `intersection`.
- `UNION_NO_MEMBER_MATCHES` · error — An action's input accepts one of several types, and the value fed to it is none of them. **Remedy:** Feed a value of one of the accepted types, or add the fed type to the input's accepted types.
- `UNKNOWN_FUNCTION` · error — The action's `functionKey` names a function the platform does not have, so the action cannot run. **Remedy:** Set `functionKey` to a function the function catalog lists, and send the `functionConfig` that function takes.
- `VALUE_BUILD_FIELD_TYPE_MISMATCH` · error — An entry under `fields` gives a value of another type than the output type's field of that name takes, such as text for a number field. **Remedy:** Change the expression at `details.field` to give `details.expected`, or change the field's type; `details.actual` is what the expression gives now. **Details:** `field`, `name`, `expected`, `actual`.
- `VALUE_BUILD_FIELD_UNKNOWN` · error — A name under `fields` is not a field of the action's output type, so the value it gives would not fit the type. **Remedy:** Rename the entry at `details.field`: `details.suggestion` is the nearest field, and `details.declared` lists every field the type has. Or add the field to the type, or remove the entry. **Details:** `field`, `name`, `declared`, `suggestion`.
- `VALUE_BUILD_REQUIRED_FIELD_MISSING` · warning — The output type requires a field that no entry under `fields` gives, so every value this action builds is refused at run time for missing it. **Remedy:** Add a field named `details.name` under `fields`, or make the field optional in the type. **Details:** `name`, `type`.
- `VALUE_BUILD_TYPE_REQUIRED` · error — A value built field by field has no output type of its own: it still answers the default `object`, so there is nothing to check its fields against. **Remedy:** Set the action's `outputSchema` to the type the value is, for example `{ref: BookCard}`; each name under `fields` must be a field of it.
- `VIEW_CALLER_WITHOUT_PERSON` · error — A flow reads a view that reads as the signed-in person (`scope: caller`) and reaches a table each person owns, and something starts that flow with no person: a schedule, a trigger, the processing of a project table, a vocabulary's resolver or an eval suite with no run-as member. The read fails every time it starts that way. The message names the start, the flow, the view and the table. **Remedy:** Start the flow once per person with `flow.start-per-person`, give the eval suite a run-as member, read the view only from flows a signed-in person calls, or make the view `scope: project` over project tables only.
- `VIEW_ENDPOINT_NOT_DERIVED` · warning — The endpoint's flow answers a view's page, but the endpoint is asynchronous or its contract declares `after`, `before` or `limit` itself, so it keeps the contract it declares: no paging, typed params or item schema from the view. **Remedy:** Nothing blocks the save. To page by the view, make the endpoint synchronous and remove `after`, `before` and `limit` from its contract and bindings.
- `VIEW_INPUT_TYPE` · error — The endpoint answers a view's page, and its flow declares an input named like one of the view's params, or like one of its `record.view` action's own paging inputs (`<action>After`, `<action>Before`, `<action>Limit`), with another type than the view gives it, so the request's value would not fit. **Remedy:** Declare the input with the type the request gives it: a cursor (`<action>After`, `<action>Before`) is a string, a page size (`<action>Limit`) a number, and a param the type the view declares.
- `VIEW_PAGING_NOT_DECLARED` · warning — The endpoint answers a view's page, but its flow declares none of its `record.view` action's paging inputs (`<action>After`, `<action>Before`, `<action>Limit`), so a request's `after`, `before` and `limit` reach nothing and the endpoint answers only the first page. **Remedy:** Nothing blocks the save. Declare the inputs the message names on the flow, each optional; after renaming the action, rename them with it.
- `VIEW_PAGING_SLOTS_COLLIDE` · error — Two `record.view` actions of the flow page by the same slots: each pages by slots named after the action with dashes and dots dropped (`read-shelf` by `readShelfAfter`), so `read-shelf` and `read.shelf` would share one cursor. **Remedy:** Rename the actions in `details.actionNames` so their names differ in more than dashes and dots, and rename their paging inputs with them. **Details:** `slot`, `actionNames`.
- `VIEW_PARAM_FROM_ACTION` · error — A `record.view` action reads a view whose param is named like an action's output, or an action's output is named like the `record.view` action's own paging input (`<action>After`, `<action>Before`, `<action>Limit`). A view's params and paging come only from the flow's inputs: nothing orders the read after the action, so it could read before the value is written. **Remedy:** For a view param: filter by the computed value with an inline `record.query` that takes the slot, or rename the output in `details.producer` and pass `details.param` as a flow input. For a paging input: rename the output in `details.producer`, and pass `details.param` as a flow input to set the page. **Details:** `view`, `param`, `producer`.
- `VIEW_PARAM_NO_INPUT` · error — A `record.view` action reads a view whose param has no default and is not optional, and the flow takes no input of that name, so every run would fail. **Remedy:** Add `details.param` as an input of the flow, or give the param of the view in `details.view` a default or make it optional. **Details:** `view`, `param`.
- `VIEW_PARAM_OPTIONAL_NO_INPUT` · warning — A warning: a `record.view` action reads a view whose optional param no input of the flow is named like, so the read never narrows by it and returns every record the param would filter out. A param renamed in the view while the flow keeps the old input name says this. **Remedy:** Add `details.param` as an input of the flow (or rename the flow's input to it). Nothing blocks the save when the flow means to read without that filter. **Details:** `view`, `param`.
- `VOCABULARIES_RESOLVE_DETERMINISTIC_SLOT_UNRESOLVED` · error — A deterministic slot of a `vocabulary.resolve` action (`details.slot`) has no action writing it, so its vocabulary resolves nothing and the model's proposal for it is skipped. **Remedy:** Point the entry at a slot an earlier action writes, or remove it to let the proposal run. **Details:** `slot`, `vocabularyKey`.
- `VOCABULARIES_RESOLVE_EXTRACTION_SLOT_UNRESOLVED` · error — An extraction slot of a `vocabulary.resolve` action (`details.slot`) has no action writing it, or what writes it has no field matching a project vocabulary. **Remedy:** Point the extraction slot at a slot an earlier action writes whose fields are marked with the project's vocabularies, or remove it. **Details:** `slot`.
- `VOCABULARIES_RESOLVE_MISSING_ANCESTOR` · error — A `vocabulary.resolve` action lists a child vocabulary in `vocabularyKeys` without its parents (`details.missingAncestors`). **Remedy:** Add the whole parent chain of each listed vocabulary to `vocabularyKeys`. **Details:** `vocabularyKey`, `missingAncestors`.
- `VOCABULARIES_RESOLVE_OUTPUT_DOUBLE_PERSIST` · warning — A `vocabulary.resolve` output (`details.outputSlot`) is saved by more than one `term.upsert` action, so every term would be written more than once. **Remedy:** Nothing blocks the save. Keep one `term.upsert` action reading that slot. **Details:** `outputSlot`, `actionCount`.
- `VOCABULARIES_RESOLVE_OUTPUT_UNPERSISTED` · warning — A `vocabulary.resolve` action resolves terms into a slot (`details.outputSlot`) that no `term.upsert` saves, and nothing else reads it. **Remedy:** Nothing blocks the save, but the terms are thrown away. Feed the slot to a `term.upsert` action, or, in a sub-flow, to a flow output the caller saves. **Details:** `outputSlot`.
- `VOCABULARIES_RESOLVE_SEMANTIC_VOCABULARY_UNBOUND_RESOLVER` · error — A `vocabulary.resolve` action resolves a vocabulary (`details.vocabularyKey`) that matches by meaning and has no resolver flow, so the run would fail. **Remedy:** Bind a resolver flow in the vocabulary's settings, or switch the vocabulary to exact matching. **Details:** `vocabularyKey`.
- `VOCABULARIES_RESOLVE_UNKNOWN_VOCABULARY` · error — A `vocabulary.resolve` action names a vocabulary (`details.vocabularyKey`) that is not one of the project's, in `vocabularyKeys` or through an extraction producer's output. **Remedy:** Create the vocabulary in the project, or correct or remove the key. **Details:** `vocabularyKey`, `slot`.
- `VOCABULARIES_RESOLVE_VOCABULARY_DOUBLE_SOURCED` · error — A `vocabulary.resolve` action sources one vocabulary (`details.vocabularyKey`) both through `vocabularyKeys` and through an extraction slot. **Remedy:** Resolve each vocabulary through exactly one of the two. **Details:** `vocabularyKey`.
- `VOCABULARIES_RESOLVE_VOCABULARY_EMPTY` · warning — A `vocabulary.resolve` action resolves a vocabulary (`details.vocabularyKey`) that has no terms and cannot gain any by matching, so it never matches anything. **Remedy:** Nothing blocks the save. Add terms to the vocabulary, or let it create terms; for an exact-matching vocabulary, switch it to matching by meaning. **Details:** `vocabularyKey`.
- `VOCABULARIES_RESOLVE_VOCABULARY_NOT_SURFACED` · warning — A `vocabulary.resolve` action writes vocabularies (`details.vocabularies`) onto tables whose types do not link them, so their values would never be read back. **Remedy:** Nothing is lost by saving now. Link each vocabulary to the table's type in the type's vocabularies settings. **Details:** `vocabularies`, `tables`.
- `VOCABULARY_FIELD_STILL_READ` · error — The delete was refused: actions still read the vocabulary's field off the records of the tables that surface it, and would read nothing there. One finding per action, at its document path, names its flow and the path it reads. **Remedy:** Change each named action to stop reading the vocabulary's field first, or delete the vocabulary and change the actions in one project document.

## Rule names

- `ACTION_EVALUATE_SLOT_INVALID` · `details.reason` — A value given to `POST /v1/actions/evaluate` in `slots` is keyed by a name the action does not read, or does not fit the type the action reads it as. Nothing ran. It arrives as `details.reason` on a 422 `VALIDATION_FAILED` and as each issue's `code`; the issue's `field` names the slot, and its `issue` says which (`not-read` or `wrong-type`). **Remedy:** Key `slots` by the names the action reads its inputs under, and give each a value of its type; a read's input is its whole answer, and the message names every member that does not fit. **Details:** `reason`, `issues`.
- `BASED_ON_OTHER_PROJECT` · `details.reason` — A project document planned on one project names, in its `basedOn`, a read of another project, so nothing says what changed here since. It arrives as `details.reason` on a 422 `VALIDATION_FAILED`, and as the `code` of its one issue, at `basedOn`; the envelope `code` stays `VALIDATION_FAILED`. **Remedy:** To apply the file to this project, plan it against this project as it is now: send `?basedOn=<details.version>`. `details.readFrom` names the project the file was read from. **Details:** `reason`, `readFrom`, `project`, `version`.
- `COMPUTED_ACROSS_OWNERS` · `details.reason` — The related table holds people's own records, and the relation can link records of different owners. Only how many related records there are may be kept, never their values. **Remedy:** Use a plain `count` with no `where`.
- `COMPUTED_CHAIN_TOO_DEEP` · `details.reason` — A computed field is built on a chain of computed fields longer than the platform follows. **Remedy:** Read a stored field somewhere along the chain.
- `COMPUTED_DIRECTION_REQUIRED` · `details.reason` — The relation links this table at both ends, so which related records are meant is ambiguous. **Remedy:** Add `direction`: `incoming` for records that link to this one, `outgoing` for records this one links to.
- `COMPUTED_DISTINCT_TOO_LONG` · `details.reason` — A `distinct` list keeps more values than the platform allows. **Remedy:** Lower `max`.
- `COMPUTED_FIELD_CYCLE` · `details.reason` — Computed fields read each other in a circle, so none of them could be worked out first. **Remedy:** Break the circle: one of the fields must read only stored fields.
- `COMPUTED_FIELD_NAME_TAKEN` · `details.reason` — A computed field takes a name the record already uses: a submitted or flow-output field of the table, a vocabulary it surfaces, or a name every record carries (`status`, `computing`, …). **Remedy:** Pick another name. To turn a submitted field into a computed one, remove it from the table's type in the same change.
- `COMPUTED_FILTER_TYPE_MOVED` · `details.reason` — A table filters on one of its computed fields, and this change would give that field a different type than its filter was set up for. **Remedy:** Keep the type the field reads, or save that table's `uses` again in the same change so its filter follows the new type.
- `COMPUTED_FORMULA_ASSERT` · `details.reason` — A table's health: a formula's `$assert` failed on a record, so that record's value was left out. **Remedy:** Read `lastFailure.recordId`; fix the record's fields or the formula's assertion.
- `COMPUTED_FORMULA_EXAMPLES_OVER_BUDGET` · `details.reason` — A save's formula examples took longer than one save may spend running examples, so the rest could not be checked and the save is refused. **Remedy:** Save fewer formulas with examples at once, or give them fewer or smaller examples.
- `COMPUTED_FORMULA_EXAMPLE_MISMATCH` · `details.reason` — A formula's example answers something other than the value it states, or does not run. **Remedy:** Fix the formula, or the example's `value`, so the formula answers it for that `row`.
- `COMPUTED_FORMULA_FAILED` · `details.reason` — A table's health: a formula could not be evaluated for a record, so that record's value was left out. **Remedy:** Read `lastFailure.recordId` and check the formula against that record's fields.
- `COMPUTED_FORMULA_FIELD_UNKNOWN` · `details.reason` — A formula reads a field the table does not have. **Remedy:** Read one of the table's own fields, including its other computed fields.
- `COMPUTED_FORMULA_INVALID` · `details.reason` — A computed field's formula is not a JSONata expression that parses. **Remedy:** Fix the expression; the message names where it stops parsing.
- `COMPUTED_FORMULA_NOT_DETERMINISTIC` · `details.reason` — A computed field's formula reads the clock or a random value, so its value would change without the row changing. **Remedy:** Compute from the row's own fields only; store a time as a submitted field and read it.
- `COMPUTED_FORMULA_TIMEOUT` · `details.reason` — A table's health: a formula took longer than its time allowance on a record, so that record's value was left out. **Remedy:** Simplify the formula; it reads only the record's own fields.
- `COMPUTED_FORMULA_TYPE_MISMATCH` · `details.reason` — A table's health: a formula answered a value of another type than the one it is typed with (its examples' type) for a record, so that record's value was left out. **Remedy:** Read `lastFailure.recordId`; make the formula answer the same type for every record, or give it an example that shows the other answer.
- `COMPUTED_LOOKUP_NOT_MANY_TO_ONE` · `details.reason` — A `lookup` reads the one record this record links to, and this relation either links in the other direction or can link several. **Remedy:** Use a many-to-one relation this table's records link out through, or a `rollup`.
- `COMPUTED_PEERS_OVER_CEILING` · `details.reason` — Some record already has more related records than one computed value may summarise, so its value could never be kept. **Remedy:** Narrow the field with `where`, or summarise a smaller relation.
- `COMPUTED_PEER_FIELD_NOT_FILTERABLE` · `details.reason` — A computed field reads a related field that is not a `filter` field, so Kipory cannot read it from its index. A save that removes such a `filter` use is refused the same way. **Remedy:** Mark the related field `filter` in its table's `uses` (in the same change is fine), or keep its `filter` use.
- `COMPUTED_PEER_FIELD_NOT_NUMBER` · `details.reason` — A `sum` or `avg` reads a related field that is not a number. **Remedy:** Name a number field.
- `COMPUTED_PEER_FIELD_UNKNOWN` · `details.reason` — A computed field reads a field the related table does not have. **Remedy:** Name a field of the related table.
- `COMPUTED_PEER_TABLE_REQUIRED` · `details.reason` — The relation links this table to several tables, so which one to read is ambiguous. **Remedy:** Add `peerTable` naming the related table.
- `COMPUTED_RECOMPUTE_FAILED` · `details.reason` — A table's health: recomputing a record's computed values failed, so Kipory kept its old values and tries that record again in a minute. The project's other records are not held up. **Remedy:** Read `lastFailure.recordId`. If it keeps failing, report it: the record's values cannot be kept until it is fixed.
- `COMPUTED_RELATION_NOT_COUNTABLE` · `details.reason` — The relation links through join records, which hold no links Kipory can summarise. **Remedy:** Use a relation produced from a field, or by curated links.
- `COMPUTED_RELATION_NOT_REACHING` · `details.reason` — The relation a computed field names does not link this table (in the direction given), or does not link the `peerTable` given. **Remedy:** Name a relation whose pairs include this table, or add the pair to the relation.
- `COMPUTED_RELATION_UNKNOWN` · `details.reason` — A computed field names a relation this project does not have. **Remedy:** Name a relation that links the related table to this one.
- `COMPUTED_RENAME_INVALID` · `details.reason` — `renameComputed` names a field the table does not have as a computed field, still declares the old name, or names a new one `computed` does not declare (or the table already has). **Remedy:** Name a computed field the table has as the old name, and declare it in `computed` under the new name only.
- `COMPUTED_TOO_MANY_FIELDS` · `details.reason` — The table declares more computed fields than one table may hold. **Remedy:** Remove the computed fields the table does not need.
- `DOCUMENT_APPLY_FAILED` · `details.reason` — A project document could not be applied, so nothing was written — on `POST /v1/projects` no project was created and its address is still free. It arrives as `details.reason` on a 422 `VALIDATION_FAILED`. **Remedy:** Read `details.plan`: its `diagnostics` name each refusal with its path in the document. Fix those parts of the document and apply it, or create the project, again. **Details:** `reason`, `plan`.
- `EFFORT_UNSUPPORTED` · `details.reason` — The binding's `reasoningEffort` is not one this model accepts, or the model takes no effort setting at all. It arrives as `details.reason` on a 422 `VALIDATION_FAILED`. **Remedy:** Send an effort from the model's `reasoningEfforts` on `GET /v1/ai-models`, or omit `reasoningEffort` for a model whose list is empty. **Details:** `reason`.
- `EMBEDDING_PROFILE_ACTIVATION_REFUSED` · `details.reason` — Activating this generation was refused because a table on the profile could not move to it, or the generation's model no longer resolves. The message lists each table and what is wrong; nothing moved. **Remedy:** Fix what the message names on each table (usually a field the search declaration names that no longer exists), or mint a generation on a model that resolves, then activate again.
- `EMBEDDING_PROFILE_DEFAULTS_REFUSED` · `details.reason` — Changing the profile's default was refused because one or more tables that inherit it cannot take the new value. The message names each table and its own refusal; nothing was changed. **Remedy:** Fix those tables first or give them their own `uses.search.chunking`, then send the profile change again. A 409 here means a table was mid-change: re-read and retry.
- `EMBEDDING_PROFILE_GENERATION_UNCHANGED` · `details.reason` — The new generation would use the same model and the same `keywords` as the current one, so minting it would only cost a full reindex to reach the same place. **Remedy:** Change `modelId` or `keywords` in the mint. To change only the label, send a PATCH to the profile instead.
- `EMBEDDING_PROFILE_GEOMETRY_UNRESOLVED` · `details.reason` — The embedding model named in `modelId` cannot index anything: it is not in the model catalog, is not an embedding model, or has no usable distance metric. The message says which. **Remedy:** Choose another embedding model, one with recorded dimensions and a Cosine or Dot distance, and send the create or mint again.
- `EMBEDDING_PROFILE_IN_USE` · `details.reason` — A searchable table still uses this embedding profile generation, so the delete is refused with 409; the message names the tables. A profile read shows it as `deleteRefusal`. **Remedy:** Remove `search` from those tables' `uses`, or activate a different generation, then delete.
- `EMBEDDING_PROFILE_KEY_DUPLICATE` · `details.reason` — A profile with this key already exists in the project, so a second one cannot be created under it. **Remedy:** Pick a different `key`, or mint a new generation of the existing profile if you meant to change its model.
- `EMBEDDING_PROFILE_KEY_INVALID` · `details.reason` — The profile `key` is not lowercase kebab-case. The key becomes part of the name of every index the profile builds. **Remedy:** Send a key of lowercase letters and digits joined by single hyphens, such as `article-search`.
- `EMBEDDING_PROFILE_MODEL_RETIRED` · `details.reason` — The embedding model is retiring or retired, so a new profile or generation cannot embed through it. **Remedy:** Choose another embedding model for `modelId` and send the create or mint again.
- `ENDPOINT_PATH_CONFLICT` · `details.reason` — An endpoint's method and path collide with a built-in route or with another endpoint of the project. It arrives as `details.reason` on a 409 `CONFLICT`, and as a finding on a dry run. **Remedy:** Change the endpoint's path or method so it shadows no built-in route and no other endpoint; the message names the route or endpoint it collides with. **Details:** `reason`.
- `EVENT_PAYLOAD_SCHEMA_MISSING` · `details.reason` — An action emitted an event whose event type names a payload type the run could not find, so the payload could not be checked and the action failed. **Remedy:** Re-read the event type and point its payload at a data type that exists in the project, then run again.
- `EVENT_PAYLOAD_TOO_LARGE` · `details.reason` — An action emitted an event whose payload is over the payload size cap, so the action failed. The message names the size and the cap. **Remedy:** Emit less: carry ids or a summary in the payload and let consumers read the rest from the records.
- `EVENT_PAYLOAD_UNEXPECTED` · `details.reason` — An action emitted a payload for an event type that declares no payload, so the action failed. **Remedy:** Emit the event with no payload, or give the event type a payload type that describes what you send.
- `EVENT_TYPE_UNKNOWN` · `details.reason` — An action emitted an event whose category and key are not an event type in the project, so the action failed. **Remedy:** Declare the event type in the project, or fix the category and key the action emits, then run again.
- `EXPRESSION_NOT_REWRITABLE` · `details.reason` — An action reads the slot in an expression the rename cannot rewrite. The message names the action and why. **Remedy:** Edit that expression by hand so it no longer needs rewriting, then rename.
- `FIELD_IS_COMPUTED` · `details.reason` — A write names a computed field. Kipory keeps its value from related records or the record itself; no writer sets it. **Remedy:** Leave the field out of the write; read it instead.
- `FILE_NOT_STORED` · `details.reason` — A `file.copy` action was given a file that is no longer stored, so there was nothing to copy and the action failed. **Remedy:** Pass a file the run produced or read from a record that still holds it; a file removed since it was read cannot be copied.
- `FILE_OUT_OF_SCOPE` · `details.reason` — An action was given a file that belongs to another project or person, so this run may not read it and the action failed. **Remedy:** Pass only files this run produced or read from records it may read.
- `FILTER_VALUE_ABSENT` · `details.reason` — A read action filters on a value it takes from the run, and the run did not supply that value, so the records were not read without the filter and the action failed. A flow endpoint answers it as a `409 CONFLICT`. **Remedy:** Make sure the slot the filter reads holds a value before the action runs, or guard the action with a `condition` so it runs only when the value is there.
- `FILTER_VALUE_INVALID` · `details.reason` — A read action filters on a value it takes from the run, and the value there is not one the filter can compare: a list or an object where one text, number or true/false value was expected. The action failed. **Remedy:** Pass one text, number or true/false value in the slot the filter reads, shaped as the message says.
- `INVOKE_FLOW_UNRESOLVED` · `details.reason` — An asynchronous invocation failed before it started because the flow its endpoint is bound to no longer exists in the project. **Remedy:** Bind the endpoint to a flow that exists, then call it again. The failed invocation is not run again.
- `INVOKE_INPUTS_UNCOVERED` · `details.reason` — An asynchronous invocation failed before it started because the bound flow now requires input slots the invocation gave no value for. The message names them. **Remedy:** Send a value for each named slot, or make those slots optional on the flow, then call again.
- `LINKED_JOIN_RECORD` · `details.reason` — A linked read names a relation whose links are records of a table of their own; `linked` does not follow such relations. **Remedy:** Read the link table's records with a linked read on each of its relations, or read them with `record.query` and a link clause.
- `LINKED_LIST_NEEDS_LIMIT` · `details.reason` — A linked read answers a list (incoming, many-to-many, symmetric, or a relation with no declared cardinality) and sets no `limit`. **Remedy:** Set the linked read's `limit` to the most records you need for each record read, at most a page of records (`runs.record-page-rows`).
- `LINKED_NO_PAIRING` · `details.reason` — A linked read's relation does not connect the table being read in the linked read's `direction`, so the linked read could never bring a record. **Remedy:** Set `direction` to the other way (`"outgoing"` from the side that points, `"incoming"` from the side pointed at), or add the pairing to the relation.
- `LINKED_ONE_TAKES_NO_LIST_OPTIONS` · `details.reason` — A linked read answers one record (outgoing on a relation declared many-to-one) and sets `limit`, `sortField`, `order` or `onMore`, which only a list takes. **Remedy:** Remove `limit`, `sortField`, `order` and `onMore` from the linked read; the linked record arrives as one object.
- `LINKED_RELATION_UNKNOWN` · `details.reason` — A linked read names a `relation` the project does not declare, so the action was not saved. **Remedy:** Set the linked read's `relation` to the key of a relation the project declares, or create that relation first.
- `LINKED_SORT_NOT_DATE` · `details.reason` — A linked read's `sortField` is not a date field with a `filter` use of the table at the other end, so its records cannot be ordered by it. **Remedy:** Set `sortField` to a date field of the other table with a `filter` use (add `filter` to the field's `uses` if it is a date without one), or leave it out to order by created time.
- `LINKED_TABLE_NOT_AT_END` · `details.reason` — A linked read's `table` is not a table the relation reaches from the table being read in the linked read's `direction`. **Remedy:** Set `table` to a table the relation pairs with the table being read, or leave it out when only one table is at the other end.
