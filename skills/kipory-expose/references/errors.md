# Errors a caller of a product endpoint meets

<!-- field-ok: windowMs — a key inside the rate limiter's error `details`, declared in the middleware rather than a wire contract -->

Read this when a call to a product endpoint on the project host is refused or fails: the error envelope and every code a caller can get, with what to do.

## The error envelope

`{ code, message, details?, requestId }`. **Branch on `code`**; the message may change at any time. `requestId` is also the `x-request-id` response header — and on a synchronous invocation it **is the run id** for `GET /v1/runs/{runId}` on the api host.

| Status | `code`                                                        | When                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 401    | `UNAUTHORIZED`                                                | no, malformed or unknown credential; dead session                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 402    | `BALANCE_BELOW_SOFT_CAP`                                      | the wallet is below its soft cap: a non-GET up front, or any call whose run it stops at a paid step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 402    | `USER_SPEND_CAP_EXCEEDED`                                     | the acting person hit their own ceiling on a healthy wallet                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 400    | `BAD_REQUEST`                                                 | `The flow attempted a blocked network request.` — a fetching step was handed a URL that is not `http(s)`, is malformed, or resolves to a private address. A name that does not resolve at all is not this: it is the `502` below with `details.phase: "target-unreachable"`. Validate URLs before sending them                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 403    | `FORBIDDEN`                                                   | grant does not reach the project; VIEWER on a write; not a member; key on a person-scoped step — including a key calling an endpoint whose flow reads or writes person-owned records                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 403    | `WORKLOAD_SUSPENDED`                                          | the project, or an organisation above it, is suspended or archived: every call that runs a flow is refused before its first step, on any credential. `details.effectiveStatus` says which. A `suspended` hold is lifted only by the deployment's operator. An `archived` organisation is reactivated by one of its admins, signed in: `PATCH /v1/nodes/{nodeId}/status` with `{ "status": "active" }` on the api host, which refuses an API key                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 404    | `NOT_FOUND`                                                   | unknown host; no match or wrong method; the route's group is disabled (`This API is not enabled for this project.`); the endpoint's flow is gone                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 404    | `RECORD_NOT_FOUND`                                            | the flow read a record by id and found none (`The requested record was not found.`) — a deleted or mistyped record, not a missing endpoint                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 409    | `CONFLICT` / `CHANGE_SET_PRECONDITION_CONFLICT`               | a run precondition was unmet (a record not in the state an update requires); a record changed mid-run and nothing was written                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 409    | `RECORD_NATURAL_KEY_TAKEN`                                    | a record the flow writes carries a natural key another record of its table already holds; nothing was written. `details.holderRecordId` is the record that holds the key, the one to update, `details.refusedRecordId` the id the refused write would have had                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 422    | `VALIDATION_FAILED`                                           | body, query or path failed the contract, including an undeclared query key; or the flow itself refused the input (a `$assert`, a file check, a `cursor` no page answered, an id list past 200, a record missing its natural key, a record id that came up empty) — the only flow failure whose message reaches the caller, beside a `fail` step's own 4xx. Each of `details.issues[]` is `{ instancePath, keyword, params, message, in }`, `in` naming `body`, `query` or `path` — the shape the design API's 422s use too. A body field bound to a flow input that breaks the input's type also carries `details.reason: "FLOW_INPUT_INVALID"`, the run code for a flow input that breaks its signature, with `flow`, `input`, `path` (where inside the input) and `expected`                                                                                                         |
| 422    | `FLOW_OUTPUT_MISSING`                                         | no step failed, but the flow gave no value for a required output (a backstop: a `return` missing one already fails `502 FLOW_FAILED` with `OUTPUT_TYPE_MISMATCH`); `details.missing` names the output fields. Nothing the run staged was written: the refusal is decided before its writes apply. Not retryable as is — the flow needs fixing, or the input that leads down that path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 4xx    | `REQUEST_REFUSED`                                             | a `fail` step of the flow chose a status that has no code of its own here — any 4xx other than 405, 408 and 426 without one, such as 400, 402 or 418 (a `fail` 404, 409 or 422 answers `NOT_FOUND`, `CONFLICT` or `VALIDATION_FAILED`). `details.reason` is the `fail` step's own `code`, and the message is the one it wrote                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 429    | `RATE_LIMITED`                                                | the per-minute limiter (`details` carries `limit`, `windowMs`, `retryAfterSeconds`, the refusing limit's key as `limitKey` — look it up on `GET /v1/projects/{nodeId}/limits` — and a `retry-after` header); `details.scope: "project"` when the whole project, not this caller, is over its per-minute ceiling — including a step of the flow over the project's own limit for its function (`limitKey` `functions.<bucket>.calls-per-window`, such as 300 meaning searches a minute): the step waited its turn, then the flow stopped and nothing it staged was written                                                                                                                                                                                                                                                                                                              |
| 429    | `QUOTA_EXHAUSTED`                                             | a step met a quota that starts again later: a third-party data API's quota, such as the YouTube Data API's daily units, or the credit of the project's own key at a provider (`details.limitKey` when a project limit counted over a period refused it). It is the project's quota, not your caller's, and no `retry-after` is sent: do not retry in a loop, the same call fails until the quota starts again. The platform's own model-provider account out of quota is not a 429: it is the `503 PLATFORM_DEPENDENCY_UNAVAILABLE` below. A limit of how much one run may do, and the daily mail and push caps, are the `502 FLOW_FAILED` below                                                                                                                                                                                                                                       |
| 429    | `PROJECT_CONCURRENCY_EXCEEDED`                                | the project already has its maximum of requests running or streams open (`details`: `scope`, `kind` `requests`/`streams`, `limit`, `retryAfterSeconds`, plus `retry-after`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 502    | `FLOW_FAILED`                                                 | a step failed (`details.phase` says which kind and `details.step` names the step by its key; nothing it staged was written; a mail step refused for its sender adds `details.reason`, `address-not-available` or `domain-not-sendable`, one whose recipient is not an email address adds `recipient-not-an-address`, and one past the project's daily mail or push cap adds `project-mail-cap-reached` or `project-push-cap-reached` with `details.limitKey`; a step the run rule refused adds its code as `details.reason`, below the table) — its message is on that step's timeline row; a run that reached a limit of how much one run may do (`details.class: "limit"` and `details.limitKey`, with `phase` and `step` when a step met it; the same request fails the same way); the output failed the response contract (checked before the writes apply, so nothing is written) |
| 503    | `PLATFORM_DEPENDENCY_UNAVAILABLE`                             | the platform's own failure: one of its vendor or model-provider accounts refused a step's call (`details.phase` is `platform-fault`, `details.step` names the step), the engine itself failed, the database refused the run's changes (`details.class` says which platform class), or a check made before serving — the credit check, a public endpoint's rate count, the project's sign-in settings — failed. `details.retryAfterSeconds` and a `retry-after` header say when to try again. Nothing is wrong with the request or the flow, nothing the run staged was written, and a failed step is not charged. Whoever runs the deployment is alerted to each: a refused platform account and a run the platform failed where they happen, a check that failed before serving once it fails again within minutes                                                                    |
| 503    | `TEMPORARILY_UNAVAILABLE`                                     | the platform's database could not answer in time, on any request, including a check made before serving (`details.retryAfterSeconds` and a `retry-after` header say when to try again). It is not a verdict on the credential: do not sign the person out — a 401 or 403 is a verdict, this is not. Retry a read after the wait, backing off if it repeats; a write may already have landed, so retry it only if repeating it is safe or you have checked its result                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 503    | `STREAM_CAPACITY_EXCEEDED` / `STREAM_TEMPORARILY_UNAVAILABLE` | this process is at its stream limit; a stream's binding could not be established (retry shortly)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 504    | `GATEWAY_TIMEOUT`                                             | a synchronous flow exceeded its timeout; the run may have completed, so check before retrying                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

**409 `FLOW_NOT_AUTHORED`**: the flow has no steps yet, so it was not started (`details.flowKey`). Do not retry until its steps are written.

The run-rule codes a `502 FLOW_FAILED` names as `details.reason`: `STEP_INPUT_ABSENT` (a required input was nothing), `STEP_INPUT_EMPTY` (an input that must not be empty was), `STEP_INPUT_REFUSED` (a fetch handed a value it cannot read), `OUTPUT_TYPE_MISMATCH` (a step's answer, or a `return`, broke its declared type, a required output given nothing included), `FLOW_INPUT_INVALID` (a sub-flow call's inputs broke the called flow's signature), `EACH_OVER_NOT_A_LIST`, `EACH_OVER_MAX_ITEMS`, `FAN_OUT_OVER_LIMIT`, `REPEAT_PASSES_EXHAUSTED` (a `repeat` ran out of passes) — and, when it names one, the read or output as `details.path`.

The 402 codes in the table have **opposite remedies** — the wallet needs credit, which no route of yours adds (tell the human which wallet; the deployment's operator credits it), or that person's cap needs raising. A suspended wallet answers `BALANCE_BELOW_SOFT_CAP` too, with `details.reason: payer_suspended`. A project that turned member wallets on adds a third for a signed-in member whose own wallet is empty, `MEMBER_WALLET_EMPTY`; `kipory-connect`'s `references/conventions.md` lists every 402 code with its remedy and `kipory-operate` has the detail. The credit gate does not refuse a GET up front, so an over-cap project degrades to read-only rather than dark; a GET whose flow reaches a paid step (a model call, a search, an outside call) is asked at that step and answers `BALANCE_BELOW_SOFT_CAP` before it runs.
